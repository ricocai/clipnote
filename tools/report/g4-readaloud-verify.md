## 任务项逐项结论

### 1. 断网朗读（正文不联网发送）

- **静态核验通过**：`speech/` 全模块零网络 API（grep `fetch|http|@ohos.net|socket` 无命中）；朗读链路与渲染链路的网络拦截（G6 远程 404）互不依赖；`SystemTtsDriver` 固定 `online:1`（系统引擎离线-only），无在线兜底分支，满足 §4.6「不得静默转在线后仍标注文本不出设备」。
- **运行时终验 = 真机**：飞行模式 createEngine+speak 全链路（probe §5-1）。

### 2. 长文连续朗读（≥10 分钟量级）

- **主机台架 S1 通过**：21,280 字符 → 560 段（按 275 字/分折算 ≈77 分钟播放量级；≥10 分钟要求留 7 倍余量），全段恰好各播一次、顺序与计划一致、串行无双播、无异常 stop；高亮锚点 560/560 合法且段文本属于锚定块（段落级高亮正确性的映射前提）。
- **架构口径**：控制器逐段 await speak → 逻辑层无预取越界（≤windowHigh=2）、无整篇预合成，与「有界队列防内存上涨」设计一致。
- **真机待验**：实际欠载依赖 `onComplete` 时序语义——**若 onComplete 是「合成完毕」而非「播放完毕」，逐段串行会出现段间空洞/截断**（见问题清单 F-2）。

### 3. 中断/恢复

- **段边界暂停语义**有覆盖：单元用例 + 台架 S2（560 段长文中途外部事件中断 → paused + 对在播段发 stop → 恢复从在播段头重读并播完，中断原因清除）。外部事件派发模式（AVSession 焦点回调的典型形态）验证为**干净**。
- **台架 S3 复现一个窄竞态**：中断回调与段下发在同一调用栈时，`pause` 的 `engine.stop` 在引擎登记前扑空 → 被暂停段样本已入驱动且未收到 stop（真机可能表现为「按暂停后仍闻旧音」/恢复 speak 与残留样本冲突）。生产派发模型下窗口极小且外部模式已证干净——列为**加固建议**（见问题清单 F-1），并要求真机核对焦点中断事件派发形态。
- **来电/闹钟实际行为 = 真机**：probe §5-6 明示「无任何官方或社区实测证据」，为 G4 最大未知项。

### 4. 锁屏播控

- 控制面（play/pause/next/previous/stop + 元信息 + 焦点）已接线且降级路径明确（会话创建失败 → 无通知栏播控，应用内按钮可用，不阻断朗读）。
- **但整条 AVSession 面未经任何设备编译/运行**：`av-session-controls.ets` 文件头 5 条真机核对项全部未销账；本次审查补充 2 条（F-3/F-4，见清单）。
- **锁屏播控验收结论：未验证**（非「通过」也非「不通过」）。

### 5. 段落高亮准确性

- 锚点链路正确：planner 段→块下标唯一回映射（段不跨块）→ `onSegmentStart(blockIndex)` → `reader.js highlight(data-cl-i)`；`<ul>` 合并取首条下标 + 向下回退；`highlight()` 只收整数下标，无注入面（G6 CSP 用例原样通过）。
- 已知限制（设计允许）：TTS-0 按段粒度高亮，段内进度属 playType=0 PCM 后续项。

### 6. 音色/语速切换回归

- **引擎层回归通过**：台架 S4——默认参数建引擎 → idle 时 `updateSettings({person:2, speed:1.5})` 废弃旧引擎并以新参数重建 → 越界语速 5 收敛为 2、未改字段保留；叠加 `speech-engine.test.ts` 的持久化/收敛用例。
- **UI 层无法回归：V0.2 当前无任何音色/语速切换入口**（Settings/阅读页均未接线）。引擎能力已就绪，且多音色枚举本身是 TTS-2 真机项（当前仅官方确认 person=0）——是否补切换 UI 建议由总控裁决，不擅自扩范围。

### 7. TTS 不可用时 UI 显式禁用体验

- **无静默转在线**（静态核验 + 单元用例「capability 失败 → init 拒绝」）。
- **未做预禁用**：控制条只按内容可朗读性显示，不查询引擎可用性；TTS 不可用时首点才显式报「朗读失败：系统 TTS 不可用…」，且 failed 态按钮可反复重试（每次再失败）。按 §4.6「显式提示**或**禁用」的字面口径勉强达标，但属最小实现——建议进设置页/阅读页做预探测 + 置灰（F-5）。
- 另：探测建议「启动即异步初始化」未接线——首段朗读包含同步 createEngine 开销，首声延迟体验待真机测量（F-6）。

## 结论

1. **主机侧验收通过**：321/321 基线复跑全绿（独立复现，非转述）；新增 G4 台架 4 场景（长文连续/外部中断恢复/同栈竞态探针/音色语速回归）全部按预期执行；「正文不联网」静态口径成立。
2. **G4 整体不判「通过」**：按 V1.4 与 G4 探测口径，断网终验、长文实际欠载、中断/恢复实际行为、锁屏播控四项属真机项，本机无真机且模拟器不支持 TTS，无法执行——**交付为「主机侧通过 + 真机待办 G4-R」**。
3. **建议**：V0.2 的 G4 销账必须有真机联调窗口（任一 API 12+ 设备）；F-1/F-3 建议先于真机联调修复（改动小、影响播控正确性面）。
