## 三、工具级授权语义核验（§4.5.5 / F05）

- 审计最小化：三态审计只记客户端/操作/对象/结果/时间，**不记正文**（`access-policy.ts:360`、审计表 `mcp_audit`）；令牌不进入 WebView/正文/日志的口径有服务器侧用例（401/403/429/413、配对限速、证书代际凭证拒绝，见 `tools/test/mcp-server.test.ts`）。

## 四、渲染隔离 G6 现状（阻断性复验归 S4-4）

- 静态化清洗白名单：`htmlsafe.ts`（`DROP_WITH_CONTENT`/`TRANSPARENT_TAGS`/协议与 `data:image` 白名单/`attachment://` 仅 64hex），恶意 HTML 主机用例覆盖厚（`tools/test/htmlsafe.test.ts`，含实体编码绕过、复合恶意文档不变量）。
- 可信壳：ArkWeb 加载 rawfile 内 `htmlview.html`（CSP `script-src 'self'`），`onInterceptRequest` 只放行 `attachment://<sha256>`（64hex 校验）与 `resource://rawfile/` 壳自身资产，不接受任意沙箱路径（`entry/src/main/ets/pages/HtmlRead.ets:201-219,308`）。
- 口径说明：设计文档中 `notes-html://` 命名在代码中未出现（V1.4 已修正"名称本身不提供安全隔离"的口径）；实现走 `resource://` + 拦截映射，安全属性等价（映射只按授权附件 ID 查找）。
- 结论：🟡 可自动化口径已做满；含真机 ArkWeb 行为的阻断性复验按派单口径归 S4-4。

## 七、遗留风险与后续整改项

- **R-01** `notes-html://` 设计命名与实现（`resource://` + `onInterceptRequest`）不一致：安全属性等价，但设计文档 §4.6 与实现应二选一收敛命名（建议随 V0.3 文档刷新处理）。
- **R-02** entry 分享适配层（`share-intake.ets` 的 scheme 白名单与 ShareKit 分支）为 .ets 代码，不在 Node 基线内、暂无设备侧断言；建议 S4-4 或 V0.2 补 hypium 用例。
- **R-03** `GET_NETWORK_INFO` 声明先于使用，V0.2 MCP 上线前复核，未使用即移除。
- **R-04** `setPinned`/`rename`/`softDelete` 仍为 last-write-wins：单字段操作，并发语义风险接受；跨设备同步冲突归 §4.8 后续设计。
- **R-05** hypium 关键链路套件（KeyChain）在本机无 DevEco/hdc 环境，未实际执行（脚本按设计报 exit 2）；需有设备/模拟器环境跑 `npm run test:keychain` 补真机证据，纳入 V0.1 验收前清单。
- **R-06** blob CAS `putBytes` 端口自身无大小上限：入口闸已覆盖全部外部路径（分享 32MB / importImage 32MB / 备份包内单 blob 256MiB），CAS 作为内部信任端口保持不变，已在审计登记。

## 八、结论

V0.1 交付面的权限/安全自查按可自动化口径做满：最小权限声明与导出面核对通过；收件箱敏感策略与工具级授权语义（F05）核验通过；五类负向用例全部有着落（新增 7 个用例，基线 313/313 绿）。审计发现并修复 1 项高危（备份二进制损坏）、2 项中危（并发覆盖、附件大小闸）。G6 阻断性真机复验（R-02/R-05 关联）按派单口径留在 S4-4。
